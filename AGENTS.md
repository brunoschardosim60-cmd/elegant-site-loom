## Application rules

- Keep PDF layout changes independent of report selection so exported filters, route history and totals match the operational view.
- Persist registered conference state in Supabase behind authentication. Team members are confirmed accounts admitted by explicit email invitation, without a fixed member cap; shared RPCs must verify membership and all tables keep RLS. Preserve the owner's original records and never merge unrelated personal accounts automatically. Use transactional three-way merges, server-side duplicate checks and immutable authenticated audit; reject conflicting field edits. Never persist unsaved import drafts or photos or expose service-role keys.
- Isolate CTC parsing and conference transitions in a browser-safe domain module so barcode rules can be tested independently.
- Confer by the Luft CTC identifier (10 digits), as requested by the user. Preserve leading zeroes and never derive a CTC from a CT-e or NF-e key.
- Show one document editor at a time with an Add CTC button; keep all photo-imported documents accessible without rendering a long list of forms.
- Use a single operational workspace with view tabs for the ongoing conference, completed manifests and session occurrences to preserve live scan state.
- A CTC can be remanifested on a different original issue date, including to another driver. Preserve each route attempt and its receipt/audit history. Only the most recent dated attempt is a scan target; earlier unreceived attempts are shown as remanifested, never falsely marked received. Same-day, undated, repeated manifesto IDs and repeated NF rows still require resolution. Enforce this rule in both import validation and the transactional shared RPC, including stale-client receipt checks.
- Authenticated users start directly in their own records, without a Minhas demandas tab or per-member overview cards. Only the top account-bar Equipe control opens the same workspace with everyone's combined totals and normal manifest list; that team view is read-only for conference records, with a return control in the same top-bar position. These are display scopes, not separate databases or new permission boundaries. Always validate imports/scans against the whole team, resolve remanifestations globally before filtering, and persist the complete canonical snapshot, never a filtered subset. An explicit spreadsheet import may associate the importing member with an identical existing canonical manifest (demandUserIds), so both personal views include it while the team counts it once and aggregates personal receipt checks. Never silently select existing manifests or overwrite conflicting spreadsheet data. Associations are additive, server-authenticated, and do not grant new permissions. Manifest creators remain immutable; last editor and receipt actor are separately assigned by the authenticated shared RPC, visible with time, and recoverable from immutable audit where evidence exists. Client-supplied actor names never override server attribution.
- Personal receipt checks are independent per authenticated user. Offer teammate confirmations through a discreet list-header button and review dialog, not per-row icons that expand the status column. The dialog identifies manifests, CTCs and source actors and allows accepting all reviewed receipts or continuing manually; never automatically receive another user's demand. Revalidate the complete reviewed batch against current ownership, route, CTC/NF/volumes and source timestamp before saving once; if any reviewed entry changed, refresh the review without accepting a subset or newly arrived entries. Team views retain one canonical document and aggregate active confirmations without duplicate totals. Only the authenticated actor may change their receipt; acceptance binds the active source's timestamp and exact CTC/NF/volumes version. Preserve historical receipts/audit and protect stale, rerouted or revoked-source confirmations. Personal lists, tracking, completion and PDFs use personal receipt projections; persist the canonical team snapshot.
- In personal-receipt mode, scanning a CTC outside the user's associated demands locates its manifest in read-only team consultation without writing a receipt. Locating a pre by DI chooses Pending/Finished from the active personal/team route projection, not the canonical teammate completion flag. A spreadsheet automatically selected as new must require explicit linking consent if a concurrent teammate import makes it an existing shared manifest, both during file reading and after preview.
- Keep personal and team Conference and Pending lists compact: show manifest creators and last editors inside the selected manifest's History panel, not as separate lines on cards or table rows. Keep authenticated audit intact and the discreet History action accessible. In personal lists show the confirmation date/time below Conferido without the redundant author name/email; personal tracking also keeps its timestamp without the author. Show receipt authors in team views and history. Peer acceptance tooltips keep the source author's identity.
- Import the optional last-occurrence code and description from report 108 per literal NF-series. Keep Luft delivery occurrences separate from the app's document receipt state. Existing occurrence refreshes require an explicit action and exact manifest ID + CTC + NF-series matches; never add duplicates, change receipt/ownership/volumes, or erase existing occurrence values for missing source data.
- Report 108 files up to 200 MB are read locally in a cancellable worker. Stream XML and retain only Filial 06 + DIS rows, preserving original row numbers in errors. Keep independent expanded-byte, cell, shared-text and selected-row budgets; do not raise the HTTP save-body limit to match the source file size, since the XLSX is never uploaded to the server.
- Protect NF occurrence chronology in both the import planner and authenticated shared transaction. Match the declared last code in the report's Ocorrencias history to obtain its event date; do not substitute issue, delivery or receipt dates. Compare event dates first, then the report's filename generation timestamp for same-day/missing-date snapshots. Preserve and flag differing values without enough chronological evidence. The first dated source establishes a baseline for legacy undated values. Missing source metadata must not erase saved values.
- Keep per-response CSP nonces server-generated and threaded into SSR scripts; never trust a nonce from an incoming header. Preserve the same-origin server-function CSRF middleware, private/no-store responses, frame protection and bounded streamed request bodies. Browser config accepts publishable/legacy anon keys only. AI authorization requires confirmed accounts and an atomic database quota; database errors must fail closed before provider calls. Recheck invitations after taking the team lock. Never run destructive or high-volume security probes against production data; replay adversarial writes in isolated PostgreSQL fixtures.
